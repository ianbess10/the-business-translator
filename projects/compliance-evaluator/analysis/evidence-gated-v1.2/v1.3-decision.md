# Evidence-Gated Decision Pipeline v1.3 — Decision Record

## Decision

**Proceed later with a targeted, separately versioned v1.3 implementation that certifies provider compatibility before freeze. Do not modify, tune, rerun or score v1.2.**

This record selects an architecture and release controls. It does not implement v1.3, create a v1.3 workflow directory, change prompts, alter the frozen dataset or labels, call the provider, execute regression cases or author a holdout.

## Why a new version is warranted

v1.2 passed its offline boundary, isolation and evaluator tests but failed before model inference because its first strict Structured Outputs schema used `allOf`. The provider rejected the request before a response was generated. The [official Structured Outputs contract](https://developers.openai.com/api/docs/guides/structured-outputs) confirms that schema adherence applies only to the supported JSON Schema subset and that unsupported strict schemas return an error.

The failure does not provide evidence against the v1.2 business architecture. It provides evidence that the model-facing contract and the deterministic business-validation contract were combined incorrectly, and that the release process lacked provider-parity certification.

A v1.2 schema edit followed by another run would violate the frozen one-attempt boundary. The correction therefore belongs in v1.3.

## Selected v1.3 architecture

### 1. Separate transport shape from business invariants

Model-facing schemas will enforce only the supported transport contract:

- root object;
- every field required;
- `additionalProperties: false` for every object;
- supported primitive, object, array and enum types;
- supported property constraints used conservatively; and
- no unsupported composition keywords.

The response schema must not use `allOf`, `not`, `dependentRequired`, `dependentSchemas`, `if`, `then` or `else`. Keywords that are not positively established in the documented supported subset must not carry a release-critical control.

Cross-field rules remain mandatory but move into deterministic post-response validation. Examples include:

- exact source support requires no unsupported elements;
- partial or unsupported source statements require identified unsupported elements;
- complete mappings require at least one current control and no uncovered elements;
- partial mappings require current controls and uncovered elements;
- no-suitable-control outcomes require no current controls and at least one uncovered element;
- current and candidate control lists must contain no duplicates, remain disjoint and respect submitted-mapping membership; and
- evidence output cannot change mapping membership.

Provider-constrained shape and deterministic semantic validity must both pass before a stage output can enter policy composition.

### 2. Add a documented provider-subset audit

The future v1.3 test suite and preflight will recursively inspect every model-facing schema.

The audit must:

- reject unsupported composition keywords anywhere in a schema;
- enforce root-object, required-field and `additionalProperties: false` rules;
- maintain an explicit allowlist aligned to the pinned provider contract;
- report the exact schema path and keyword for every violation; and
- fail before any benchmark execution marker or API request is created.

General Draft 2020-12 validation remains useful for local examples, but cannot stand in for this provider-subset gate.

### 3. Certify each exact schema against the provider before freeze

Static validation cannot prove the remote contract has not changed or that the request wrapper is correct. Before v1.3 is frozen, each of the three exact response schemas must therefore be submitted once using a generic, non-benchmark sentinel input:

1. source/support contract certification;
2. mapping contract certification; and
3. evidence contract certification.

These three calls are development contract evidence, not regression evidence. They must not use any of the 24 case inputs, evaluator labels or expected decisions, and their generated content must not be scored as model quality.

The certification record must preserve the model snapshot, endpoint, response-format name, schema hash, response ID, acceptance status and timestamp. All three contracts must be accepted before the workflow is frozen.

If a contract is rejected during development, the failure may inform v1.3 implementation before freeze. Once the schemas are certified and frozen, no further schema adjustment is permitted without a new version.

### 4. Bind regression permission to certification hashes

The v1.3 runner must refuse regression execution unless:

- the three certification records exist and passed;
- their schema hashes match the exact frozen schemas;
- their model snapshot and endpoint match the frozen runner configuration;
- the workflow metadata records zero regression runs; and
- no v1.3 results directory exists.

This makes provider compatibility an explicit release prerequisite rather than an assumption tested by the benchmark itself.

### 5. Retain strict Structured Outputs

v1.3 will not downgrade to JSON mode as an automatic fallback. JSON mode guarantees valid JSON but does not provide the same schema-adherence contract. A fallback during regression would also change the frozen execution design after observation.

Provider rejection, refusal or runtime failure must remain visible and must stop the run. No automatic alternate model, schema, endpoint or output mode is permitted.

## Controls retained without relaxation

v1.3 will retain the v1.2 operating architecture and controls:

- separate source/support, mapping and evidence stages;
- reviewed approved-obligation source-stage bypass;
- source support separated from legal readiness;
- mapping inputs isolated from evidence and escalation proposals;
- evidence outputs unable to change mapping membership;
- current controls separated from remediation candidates;
- deterministic source, applicability, assurance and escalation policy;
- catalogue owner resolution;
- cross-field reconciliation;
- identity-safe generality measurement;
- mandatory human review and `not_determined` compliance conclusion;
- runner isolation from evaluator-only labels; and
- no mock fallback, overwrite, post-result tuning or rerun.

The frozen 24 cases, labels and `gpt-4o-mini-2024-07-18` snapshot remain unchanged so any later regression result isolates the contract-layer correction.

## Expected execution shape

The pre-freeze development contract stage is expected to use **three non-benchmark certification calls**, one for each exact model-facing schema.

After certification, implementation tests and freeze, the separately authorised regression remains:

- 16 source/support assessments;
- 8 current-mapping assessments;
- 8 evidence assessments; and
- **32 regression model calls in total**.

Contract-certification calls must be reported separately and excluded from regression call counts and metrics.

## Prohibited v1.3 responses

The future implementation must not:

- edit any v1.2 workflow, schema, result or analysis artefact;
- rerun or score v1.2;
- call a 24-case regression input during provider contract certification;
- expose evaluator-only labels or expected decisions to contract tests or the runner;
- treat full JSON Schema validity as proof of provider compatibility;
- remove business invariants merely because they cannot live in the transport schema;
- use prompt wording as the sole enforcement of cross-field invariants;
- silently fall back to JSON mode, a mock provider, another model or another endpoint;
- freeze v1.3 before all three exact schemas are provider-certified; or
- combine future regression evidence with independent-validation or production claims.

## v1.3 acceptance conditions

Before freeze, v1.3 must prove:

1. all model-facing schemas pass the explicit provider-subset audit;
2. all previously valid structured examples still pass transport and semantic validation;
3. all previously prohibited cross-field states fail deterministic semantic validation;
4. duplicate, overlapping or out-of-scope control identifiers are rejected deterministically;
5. mapping and evidence payload isolation remains exact;
6. all 24 regression input paths pass offline smoke composition without labels;
7. the evaluator self-test remains 24/24 exact with all 14 gates passing;
8. the source/support, mapping and evidence schemas each pass one non-benchmark provider contract-certification request;
9. certification hashes match the exact artefacts proposed for freeze; and
10. the runner refuses regression when certification is missing, failed or stale.

Regression execution requires a later explicit instruction after the certified workflow is frozen. Any resulting run is still regression evidence, not holdout or production evidence.
