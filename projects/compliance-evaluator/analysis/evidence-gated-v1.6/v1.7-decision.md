# Evidence-Gated Decision Pipeline v1.7 — Decision Record

## Decision

**Do not tune v1.6 or implement v1.7 yet. First complete an independent, full-population dual-axis authority audit for all eight entered-assurance cases. If approved, publish a self-contained benchmark authority v1.2 and later implement a separately versioned v1.7 evaluator that fails closed when authority coverage is incomplete. Retain the v1.6 runtime architecture unless the audit identifies a genuine workflow defect.**

This record selects governance and future architecture only. It does not adjudicate `CON-008`, create authority v1.2, implement v1.7, call a provider, execute a regression, score a result or prepare a holdout.

## Why a new decision is warranted

v1.6 achieved the intended operating change. It preserved concurrent mapping and evidence conditions, retained both remediation paths and restored the missed adverse-evidence escalation. It produced 23/24 exact cases and a perfect escalation matrix.

The only mismatch is consistent with approved policy. `CON-008` has both partial coverage and a design deficiency. Benchmark authority v1.1 does not express both because it is a sparse overlay scoped to four earlier disputes.

Another workflow-rule change would tune the operating system toward incomplete measurement authority. The next control must improve authority completeness and evaluator fail-closed behavior.

## Required pre-implementation authority audit

A qualified synthetic reviewer independent of workflow coding, original label authoring, control ownership and prior adjudication approval must review all eight entered-assurance cases using:

- the source-supported approved obligation;
- every mandatory obligation element;
- current and candidate control coverage assertions;
- typed evidence requirements and observed evidence facts;
- approved composition, severity, remediation and escalation policy; and
- original label and v1.1 overlay rationales.

The review must determine for each case:

- coverage state;
- covered and uncovered obligation elements;
- evidence condition;
- all concurrent gap types;
- severity;
- all remediation actions and accountable routes;
- escalation requirement and roles; and
- the compatible headline assurance outcome.

The audit is full-population because sparse issue-driven overlays have twice left related authority assumptions outside scope.

## Benchmark authority v1.2 requirements

If the audit is approved, publish a new immutable authority version that:

- contains a complete record for every entered-assurance case;
- is self-contained rather than dependent on fallback to v1.0 decision fields;
- identifies the rulebook, composition policy and adjudication versions used;
- records dual-axis states and concurrent actions explicitly;
- includes approval and provenance metadata;
- contains no workflow predictions or score-derived exceptions; and
- prohibits retrospective v1.6 scoring.

Dataset v1.0 and authority v1.1 remain immutable historical evidence.

## Selected future v1.7 architecture

### 1. Runtime preservation by default

The source, mapping, evidence and composition runtime from v1.6 remains the selected default. The authority audit may recommend a runtime change only when it identifies a general operating-policy defect supported independently of benchmark outcomes.

### 2. Fail-closed evaluator authority coverage

The future evaluator must verify before scoring that:

- every entered-assurance case has one authority v1.2 record;
- every authority record contains both coverage and evidence dimensions;
- authority case IDs exactly match the entered input population;
- no duplicate, missing or unexpected authority record exists;
- authority, dataset and workflow versions are mutually permitted; and
- no entered decision field is silently inherited from a legacy single-axis label.

Any failure must stop evaluation before writing a score.

### 3. Preserve historical comparability

Future reporting must distinguish:

- v1.6 scored once against authority v1.1: 23/24;
- any later v1.7 score against authority v1.2; and
- independent validation, which remains unavailable.

No report may present a v1.2-authority calculation as a revised v1.6 result.

### 4. Release gates

Retain terminal coverage, zero quarantine, all mandatory escalation, zero unnecessary escalation and all-fields exact gates. Replace the sparse-overlay gate with complete dual-axis authority coverage and exact concurrent-condition gates.

No holdout may proceed unless every applicable regression gate passes.

## Required offline tests before freeze

Any future v1.7 implementation must prove:

1. authority v1.2 contains exactly all eight entered cases;
2. every entered record has complete coverage, evidence, remediation, routing and escalation fields;
3. removing, duplicating or corrupting one authority record stops evaluation before scoring;
4. no entered decision field falls back to v1.0 labels;
5. non-entered source cases retain their frozen v1.0 authority unchanged;
6. workflow, dataset and authority version mismatches fail closed;
7. concurrent partial-plus-design, partial-plus-missing and partial-plus-adverse conditions score exactly;
8. evaluator self-tests count quarantine as error and release blocker;
9. runtime code contains no benchmark identities or label access; and
10. all provider contracts retain exact certification lineage or are newly certified if changed.

## Provider certification decision

Authority and evaluator changes are offline and require no provider call. If the runtime, prompts, schemas, request wrapper, endpoint, model and temperature remain byte-identical to v1.6, provider certification may be inherited.

Any provider-facing change invalidates inheritance and requires generic non-benchmark certification before freeze.

## Prohibited responses

v1.7 must not:

- modify, rerun or rescore v1.6;
- adjudicate only `CON-008` without reviewing the complete entered population;
- edit dataset v1.0 or authority v1.1;
- remove concurrent conditions to reproduce a legacy label;
- import predictions into authority records;
- silently inherit missing entered-case fields from legacy labels;
- tune runtime policy to a benchmark case ID;
- make a provider call when contracts are unchanged;
- retry or repair an invalid provider response; or
- proceed to holdout after any failed gate.
